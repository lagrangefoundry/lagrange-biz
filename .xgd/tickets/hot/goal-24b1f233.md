Every project holds zero tickets at `draft`. Not once - as a maintained floor.

Operator, 2026-08-19 evening: *"I want to get draft tickets to 0 in every project. Obviously we will create new tickets and so it is a never ending cycle - but we have to burn down the backlog and clean up the house."*

## Why this is a goal and not a chore

`draft` is the only status that means nothing. Every other status says where a ticket is in a lifecycle; `draft` says only that someone wrote it down. A store with a large draft pile cannot answer "what is outstanding" - which makes it the same class of problem as BUG-1132, where a saturated state stopped carrying signal.

It is also where things quietly die. Two tickets I filed on 2026-08-19 morning (REQ-808, REQ-809) were closed the same day without resolution notes, most plausibly by a draft-cleanup sweep - CHAT-143 is titled "Clean up of draft bugs and reqs". That turned out fine, because the operator had independently made the calls, but the mechanism is indiscriminate: a sweep that closes drafts by age cannot distinguish a stale note from a live blocker.

Marked `in_progress`, not `aspiration`: the burn-down started this evening.

## The measurement problem, which is itself in the backlog

**`xgd ticket list --project <name>` crashes.** Reproduced live 2026-08-19:

```
File ".../lagrangefoundry/ticketing_locator/xgd_cli.py", line 275, in __getattr__
    raise AttributeError(name)
AttributeError: list_refs
```

That is xgd/BUG-1185, and it has been sitting at **`draft`** since it was filed. So the one command that would produce a cross-project draft count is broken, and the bug describing it is itself in the pile being counted. Nothing can measure this goal until that is fixed - which makes BUG-1185 the first item, not just an item.
