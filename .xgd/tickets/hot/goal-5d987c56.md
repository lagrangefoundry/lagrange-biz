## Scope, as stated by the operator, 2026-08-20

> "Check in on capability matrix <-- this is an important one that keeps slipping off the table. I need to continue to pay attention. We have not just display problems but there are bugs in the capability matrix system - it is not working perfectly and attention is required in order to ensure that we eliminate them."

Two classes, and the second is easy to lose behind the first:

1. **Display problems** - the matrix does not render correctly.
2. **Correctness defects in the matrix system itself** - how capabilities are derived, recorded or maintained.

The goal is elimination of class 2. A matrix that displays cleanly but derives wrongly is worse than one that visibly fails, because it is trusted.

## Why it matters beyond tidiness

Three things rest on it: the accountability claim in DOC-4 and DOC-8 (that trust in AI-written software must be structural rather than promised), beta credibility as the artifact distinguishing xgd from "an AI wrote some code", and DOC-19 s2.1, which makes the capability matrix the substrate for the accumulation register. A quietly-wrong matrix corrupts the very map built to track this work.

**Ordering:** a green end-to-end regression run (xgd/GOAL-1) is a precondition for trusting any matrix audit, since regression is the mechanism that exercises the matrix.
