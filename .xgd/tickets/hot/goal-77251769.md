XGD runs on the new modular lagrange-framework components rather than on its own older copies.

Named by the operator on 2026-08-11 as importing the new modular framework components, which fixes several annoying bugs as a side effect.

This is the same move as xgd/REQ-781, which imports the new AI backend so Claude invocation runs through a single choke point with a declared permissions schema. The operator reasoning there generalises: rather than implement a capability inside XGD legacy code, adopt the component that already has it. The permissions work is the first instance; the wider component import is the rest.

Worth noting what this is *not*. lagrange-framework/REQ-75 bridges to the framework ticket implementation, which XGD does not use, so it is not on this path.

The bug-fixing is a genuine side effect rather than the motivation - a class of annoying defects disappears because the newer component does not have them. That is the leverage argument in its cheapest form: fixes acquired rather than made.

Related: lagrange-framework/BUG-20 (unrecognised argument keys silently ignored) reaches a fix through this adoption, not through the framework ticket bridge.
