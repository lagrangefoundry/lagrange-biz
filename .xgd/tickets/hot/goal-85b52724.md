**Owned by xgd/GOAL-9 (Design tab creation).** That ticket is the authoritative record - spec in DOC-984, design system reference DOC-957, captured from a CHAT-138 planning session. This goal composes from it and should not be edited in parallel.

Kept here for the rationale, which is a statement about how the operator actually works rather than about the dashboard.

## Why

A feature starts as a high-level chat about requirements and architecture, becomes a design document, and then becomes REQ tickets. Chat and Docs are two halves of one activity, presented as two tabs because they were built as two features. A newcomer has no way to infer that the conversation and the document belong together.

DOC-984 is explicit that this is a consolidation rather than a relabeling: the old tab code is deleted outright, no feature flag, no fallback tab. That matches the CLAUDE.md rule against legacy modes, and it is a different risk profile from the wider component adoption (goal-77251769), which the operator noted can be run alongside the old code.
