An operator can see, at a glance, what every AI session is permitted to do - and there is one place in the code where that is decided.

**Composition:** xgd/REQ-780 (Status tab tile listing Claude session roles and their permissions) is the visibility half; xgd/REQ-781 (Claude invocation: single choke point with a permissions schema for lagrangefoundry-ai) is the structural half. Both filed 2026-08-11 within a minute of each other, both draft.

## Why this became urgent on 2026-08-11

Lunch with the n=1 external user on 2026-08-10 (see decision record). Handing someone an agent that can write to your repositories is a different proposition from running it yourself, and the question "what is it actually allowed to do" has no answer in the product today.

**This is the accountability claim, applied to XGD itself.** DOC-4 and DOC-8 both argue that trust in AI-written software has to be structural rather than promised. An AI development tool whose own permissions are invisible and decided in several places is hard to defend in a document making that argument. REQ-781 is the structural half precisely because a choke point can be audited and a scattering of call sites cannot.

There is direct evidence of the problem. On 2026-08-08 this assistant was refused a ticket create with "creating type request is not enabled for this session" - correct behaviour, but the operator had no way to see what the session was permitted to do, or to change it, without reading code. The permission existed; the transparency did not.

## Open question

Relationship to the Toolbox (lagrange-framework REQ-74, built; REQ-75 refactoring ai_ticketing onto it). Both concern what an AI may do and how that is declared. If REQ-781 is a second, parallel gating mechanism rather than the Claude-invocation-side expression of the same schema, that is two places to get permissions wrong - which is the exact argument that motivated the Toolbox in decision-46593d49.

State is aspiration rather than planned: both tickets are filed and wanted, but no work has started and no date is set. If this gates the n=1 onboarding on 2026-08-20 it needs a target date and should move to planned.
