## The turn: from branch to feature flag

xgd/REQ-801, created and free-coded 2026-08-17, is the shift. Rather than holding the permissions rewrite on a long-lived branch until it is safe everywhere, the behaviour became switchable at runtime:

- `claude_code.headless_permission_mode` and `claude_code.headless_sandbox_enabled` in `.xgd/config.yaml` (added via the template, with matching defaults in `get_claude_code_config()`).
- `xgd test-workflows --bypassPermissions true|false --os_sandbox true|false`, applied once right after `xgd init` by patching the isolated workspace own config - every later stage reads the override fresh, so no per-stage plumbing.
- `free_code` collapses into `interactive`: one canonical interactive bucket carrying builder exact `dontAsk` ruleset. No separate CLI mode, no separate role, no separate code path.

See the decision record for the reasoning.

## Outstanding - the one hard problem

xgd/CHAT-142 "Permissions hell" (2026-08-16). Seatbelt denies a write to a path the compiled policy explicitly grants.

In the `xgd-test-44c7e21f` reconcile run, a sub-agent hit a genuine kernel-level deny on `.../reconcile-BUNDLE-1/.xgd/logs/session-r6360e7e4.jsonl` - while that same session `claude_permissions_resolved` audit record, written 36 seconds earlier for the same invocation, already listed `.../reconcile-BUNDLE-1/.xgd/logs/**` under `sandbox_filesystem_allow_write`, with nothing shadowing it in the deny list. The policy XGD computes is correct. The gap is in Claude Code own `--settings` to Seatbelt compilation.

Precedent found in review: `anthropics/claude-code` issues #53891 and #56331 both show directories being auto-added to `denyWithinAllow` purely for looking config-like, invisible to user config. `.xgd/` - full of `config.yaml`, `quality.yaml`, `permissions.yaml`, `surfaces.yaml` - is a plausible trigger for the same heuristic.

Fix direction (sound regardless of exact mechanism): relocate the sandboxed child session-log write out of the dotted, config-looking `.xgd/logs/` rather than chase further per-path grants inside it. This sidesteps the failure class instead of re-diagnosing a closed-source compiler.

Also still open: a UI visibility issue reported by the operator 2026-08-15, not ticketed.

## Why it mattered enough to do properly

Trust with customers and beta testers, not operator convenience. Handing someone an agent that can write to their repositories raises a question the product could not previously answer.

It is the accountability claim applied to XGD itself. DOC-4 and DOC-8 argue trust in AI-written software must be structural rather than promised. A single choke point with a declared schema, backed by an OS sandbox, can be audited; permission decisions scattered across call sites cannot.
